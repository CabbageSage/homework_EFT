# 银行转账大作业 · Interbank Transfer Lab

通过手写银行转账系统练习工程能力，逐步理解并发、事务、幂等、部分失败和恢复。

## 已有背景

用户在此前讨论中明确提出：**“我会想完成这个，并且古法 coding，来作为我的技术练习。”** 随后讨论了这个练习对构建 Personal Agent 的帮助。

本项目按个人技术练习推进。目前没有已确认的学校题目、评分标准或提交期限。

## 协作方式

- 用户手写核心业务代码，练习建模、实现与调试。
- AI 提供需求、验收条件、概念解释、分层提示、设计审查、代码 Review 和故障场景。
- 除非用户明确要求实现代码，AI 不直接完成核心业务逻辑或给出整套答案。
- 初始化、环境检查、文档和开发工具配置可以由 AI 协助完成。

## 技术选择的状态

此前建议使用 Go，从命令行程序、模块化单体起步，再逐步引入数据库和独立服务。**这些是建议，尚未确认最终技术栈。**

## 渐进练习路线

以下是根据此前讨论整理的推进建议，按每阶段的实现和验证结果调整：

1. 账户基础：账户模型、金额表示、开户、余额查询、存取款及错误行为。
2. 单体转账与并发：明确余额守恒、禁止透支和失败时的状态约束，验证并发操作。
3. 持久化与重试：引入本地事务、交易标识、幂等处理，验证重启和重复请求。
4. 跨服务转账：模拟两个银行各自保存状态，处理超时、结果未知和部分失败。
5. 恢复与对账：验证重复消息、进程崩溃、补偿和异常交易追踪。
6. 系统演进：在正确性验证的基础上练习版本兼容、灰度与回退。

与 Personal Agent 的衔接重点是持久化执行状态、避免重复副作用、恢复中断任务及验证执行结果；后续再提炼通用机制。
